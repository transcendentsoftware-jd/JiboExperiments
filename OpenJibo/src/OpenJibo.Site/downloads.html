Fresh Linux test, separate from your working stacks

Prerequisites: Linux x86_64, Docker Compose 2.24.4 or later, Python 3, Bash, OpenSSL and unzip. Leave the original stacks and volumes intact. Download the portable ZIP first; do not pipe a remote script into a shell.

  1. Download and inspect the pinned offline verifier, saving it as verify-openjibo-starter-bundle.py.
  2. Verify before extracting. Stop on any error.
python3 -B verify-openjibo-starter-bundle.py \
  --bundle starter-portable-preview.zip \
  --expected-sha256 68f7181b4c50b08c632a482efd9f0a20be3ab3a2ad1de97fe6281a5e320b6a91

Create a new directory, extract, and inspect the README and launchers:

mkdir openjibo-published-preview
unzip starter-portable-preview.zip -d openjibo-published-preview
cd openjibo-published-preview
bash scripts/cloud/initialize-openjibo-compose-env.sh

Edit the generated .env privately to set a strong, unique OPENJIBO_POSTGRES_PASSWORD. Preserve encryption keys; do not copy sample values or paste secrets into an issue.

Create test-port.compose.yaml to use port 8082 and local speech:

services:
  api:
    ports: !override
      - "127.0.0.1:8082:8080"
    environment:
      OpenJibo__Stt__EnableAzureSpeech: "false"
      OpenJibo__Stt__WhisperThreads: "4"

The override requires Compose 2.24.4 or later. Check docker compose version. Confirm the project name is unused:

docker ps -a --filter label=com.docker.compose.project=openjibo-published-preview
docker volume ls --filter label=com.docker.compose.project=openjibo-published-preview

If either lists existing resources, stop and choose an unused project name. Then launch the pinned images without rebuilding:

docker compose -p openjibo-published-preview \
  -f docker-compose.yml -f test-port.compose.yaml \
  up -d --no-build postgres migrate api
docker compose -p openjibo-published-preview \
  -f docker-compose.yml -f test-port.compose.yaml ps -a
curl --fail-with-body --max-time 15 http://localhost:8082/health

Expected: PostgreSQL healthy, migrator exited with code 0, API running and health returns ok: true. For the current tester with a trusted checkout at ~/JiboExperiments and Node installed, test authenticated sockets:

node ~/JiboExperiments/OpenJibo/src/Jibo.Cloud/node/invoke-jetstream-compatibility-probe.mjs \
  --entrypoint-url http://localhost:8082 \
  --hub-url ws://localhost:8082 \
  --notification-url ws://localhost:8082 \
  --mode authenticated --robots 2 \
  --device-prefix published-preview --skip-turn

This deliberately creates two synthetic device records only in the new test stack. If you retained the previously verified ~/Downloads/cloud-version.ogg fixture, run:

node ~/JiboExperiments/OpenJibo/src/Jibo.Cloud/node/invoke-real-audio-probe.mjs \
  --audio ~/Downloads/cloud-version.ogg \
  --base-url http://localhost:8082 \
  --robot-id speech-acceptance-published --turns 3

Do not redirect a physical robot yet. Preserve results, image identities and bundle checksum. Acceptance evidence and probe context.

Stop the test with the same project and both Compose files followed by stop. Preserve files, keys and volumes. Never use down -v on data you wish to retain.

Installation and update roadmap

Planned installer: download, inspect, run; stable by default once a stable release exists, explicit preview opt-in, and targeted version selection. Each selection resolves to verified immutable artifacts. Portable is the default; AVX2 needs an explicit capability check. No latest/stable selector or automatic upgrade is available today.

Updates will be separate, operator-reviewed operations with backups, migration compatibility and recovery checks. Image digests and release evidence · Preview release files

Windows published-bundle acceptance remains pending. No ARM64, hybrid or managed starter certification is implied.
